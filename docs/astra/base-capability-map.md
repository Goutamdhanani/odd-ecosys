## Source-selection and foundation implications

The newer local checkout should be treated as the leading candidate for the eventual baseline only after the coordinator freezes the choice and commit/overlay. Its uncommitted changes must be reviewed before any foundation edits. The chat checkout is the older base plus a completed console redesign and should not be mistaken for the latest backend. The remote HEAD is older still.

Most useful dependency-ready foundations are the newer checkout’s persisted job patterns and restart/pause/cancel behavior (S05, S09, S10), current suppression and send-uncertainty safeguards (S16, S20), and durable AI request usage records (S07). They are reusable patterns, not acceptance. The biggest cross-cutting prerequisite is S03: core business tables remain globally keyed while workspace membership is present. S04 likewise needs an append-only event/outcome owner and transactional outbox semantics. Do not begin S05 harness ownership or S06 GLM application gateway as completed while S03/S04 and S01 remain open.

The source includes an Ollama/Bedrock application personalization path and a separate GLM tooling gateway. That is direct evidence that GLM is not yet the sole application model path. S01 commercial/source-rights and privacy gates remain `unknown` pending actual contract/license review; source code cannot resolve them. Campaign launch snapshots and per-record review should be extended to the extension’s campaign-scoped authorization envelope; the extension explicitly makes per-draft review optional and requires X14 before S33.
