# Astra foundation contracts

`harness-task-v1.schema.json` is a **design-only S00 foundation contract** for the proposed `HarnessTask` and `HarnessResult` records. It gives later S05/X01/X02 work a reviewable shape for trusted tenant-scoped references, an immutable context manifest, version pins, bounded execution limits, required outputs, deterministic completion checks, and gateway-reported usage. It is not application code, an installed harness, a completed X01/X02 implementation, or evidence that any task ran.

The selected source map is in `../base-capability-map.md`, `../extension-capability-map.md`, and `../combined-backlog.json`; source identity and overlay digest are in `../source-snapshot.json`. Contract design is useful during foundation work, while gates remain in force: S00 precedes S03; S03 precedes S04; S04 precedes S05; S05 precedes X01; X01 plus S06/S07 precede X02. S01 provider/commercial and privacy decisions remain unresolved. X01/X02 must not be marked complete until dependencies and exact acceptance tests pass.

The contract carries identifiers and immutable references rather than customer payloads. Build the context server-side from owned, permitted records; minimize personal data before any external inference; honor `NO_MODEL_EGRESS`; and use only the GLM-5.3 API for any future generative request, including graders. Unknown billing is represented as unknown, never as zero. A model response cannot change tenant scope, tool allowlists, budgets, completion rules, suppression, authorization, or workflow state. There is no send tool or execution-ticket field, and no chain-of-thought field.

The schema is syntactically strict JSON Schema 2020-12. Its refs and hashes require semantic checks beyond JSON Schema: canonicalize the manifest before checking its SHA-256; confirm every ref resolves to a real record owned by the same trusted tenant; enforce that requested outputs and completion checks match the frozen task revision; ensure model calls go through the gateway; decrement budgets for attempts whose billing is unknown; require at most one repair; detect no progress without resetting limits; and commit artifacts/check results with the workflow/outbox transaction. The schema's absolute caps of four model calls, six read-tool calls, one repair, one challenge round and 120 seconds are proposed starting defaults from the extension plan, subject to later measured policy revisions. A smaller monetary ceiling always takes precedence.

No model default, fallback provider, instantiated tenant, runtime endpoint, dependency or live execution is defined here. The schema is an input to future contract tests after S03/S05/S06/S07; source IDs, task purposes, artifact types, context sensitivity, storage key type, run identity format, cost-rate policy, retention window and completion-rubric catalogue remain decisions for their owning gates.
